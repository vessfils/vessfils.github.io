# vessfils.github.io

Personal engineering portfolio of **Jean-François Campagnolle**, Software & Machine Learning Engineer.
Live at <https://vessfils.github.io/> (after deployment).

Built with React 19, TypeScript, Vite, Tailwind CSS 4 and Motion. A fully static site, deployed to GitHub Pages by GitHub Actions.

---

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build + prerendered routes → dist/
npm run preview    # serve dist/ locally
```

Requires Node ≥ 22.18. The prerender script imports the TypeScript content files directly, which relies on Node's built-in type stripping.

| Script | What it does |
| --- | --- |
| `npm run media` | Converts images in `media-src/` to responsive WebP in `public/media/` and updates `src/content/media-manifest.json`. |
| `npm run og` | Regenerates the social preview image `public/og.png`. |
| `npm run typecheck` | TypeScript only. |

## How the code is organised

The rule: **content lives in `src/content/`, presentation lives everywhere else.** Adding or editing a project never requires touching a component.

```
src/
├── content/                  ← everything you edit to change what the site says
│   ├── site.ts               name, links, about text, experience timeline, skills
│   ├── projects.ts           every project and its full case study (typed blocks)
│   ├── types.ts              the Project / Block types that projects.ts must follow
│   ├── data/*.json           numbers behind the charts (exported from the repositories)
│   └── media-manifest.json   generated by `npm run media` — do not edit by hand
│
├── pages/                    one component per route
│   ├── Home.tsx              /            — assembles the home sections
│   ├── Work.tsx              /work        — archive with category filter
│   ├── CaseStudy.tsx         /work/:slug  — renders a project's sections A–H
│   └── NotFound.tsx
│
├── components/
│   ├── layout/               Nav (sticky bar, theme toggle, mobile menu), Footer, ScrollManager
│   ├── home/                 Hero (+ HeroField animation), SelectedWork, About, Experience, Skills, Contact,
│   │                         ProjectCard (also used by /work and "Related work")
│   ├── case/                 Blocks (turns content blocks into UI), CodeBlock
│   ├── ui/                   small reusable pieces: Img, Lightbox, Reveal, Tag, Button, ErrorBoundary
│   └── ProjectCover.tsx      the image or visual that represents a project on cards and heroes
│
├── visuals/                  charts, diagrams and demos, one file per project family
│   ├── registry.tsx          maps a visual id (used in projects.ts) to its component, lazy-loaded
│   ├── primitives/           shared building blocks: Frame, Flow, LineChart, BarList, Terminal, scales
│   ├── picture.tsx  leaf.tsx  snake.tsx  ml.tsx  systems.tsx  terminals.tsx
│
├── lib/                      helpers without UI: media.ts (srcset), inline.tsx (**bold**/`code`),
│                             theme.ts (dark/light), seo.ts (page title/description)
├── App.tsx                   routes + page transitions
├── main.tsx                  entry point
└── index.css                 design tokens (colours, fonts) and a few utilities

scripts/
├── optimize-media.mjs        media-src/ → public/media/*.webp
├── prerender.mjs             after the build: one index.html per route, 404.html, sitemap.xml, robots.txt
└── og-image.mjs              public/og.png

media-src/                    original captures (PNG/JPG), the source of everything in public/media/
```

### How a case-study page is produced

1. `projects.ts` describes a project. Its `sections` object holds lists of **blocks** — `text`, `list`, `figure`, `visual`, `metrics`, `code`, `table`, `callout`, `highlight` (see `types.ts`).
2. `pages/CaseStudy.tsx` renders the sections in a fixed order (context → approach → architecture → highlights → visuals → results → challenges → lessons) and skips empty ones.
3. `components/case/Blocks.tsx` turns each block into UI. A `visual` block looks its id up in `visuals/registry.tsx`, which lazy-loads the right component (and its data) only when the page needs it.

### Design tokens

All colours are CSS variables in `src/index.css`, defined once for dark and once for light. Tailwind classes such as `bg-surface`, `text-muted` or `border-line` read them. The four chart colours `--c1…--c4` were checked for colour-blind separation and contrast on both backgrounds. Change them there, not in components.

## Adding a project

1. Put screenshots in `media-src/<project>/` and run `npm run media`.
2. Add an object to the `projects` array in `src/content/projects.ts`, following the `Project` type. Use an existing project as a template; TypeScript flags any missing field.
3. Reference images with `{ type: 'figure', images: [{ src: '<project>/<file-without-extension>', alt: '…' }] }`.
4. For a custom chart or diagram: write a component in `src/visuals/`, add its id to `VisualId` in `types.ts`, register it in `visuals/registry.tsx`, then use `{ type: 'visual', id: '…' }`.
5. Set `featured: true` to show it in "Selected work" on the home page (keep it to around six).

The archive, routes, sitemap and "Next project" links update automatically.

## Where the figures come from

Nothing on the site is invented. Every number or image was produced as follows. The original project repositories were **only read** — all runs used copies.

| Project | Source of figures and images |
| --- | --- |
| PICTURE IA | Internship report and data-science seminar deck (internal Veolia evaluation). No Veolia imagery: all visuals are original schematics. |
| Leaffliction | Saved checkpoint `leaf_cnn.pth` re-evaluated on the repository's test split (97.2 %, 723 images). Transformation images produced by the project's own `Transformation.py`. |
| Learn2Slither | Saved model `10000_model_sansBFS.pth` with its matching code version (commit `f7db27e`). 200 greedy games for the statistics. Gameplay frames drawn by the project's Pygame renderer (headless) and assembled into `public/media/learn2slither/gameplay.webp`. |
| Kernel From Scratch | Kernels built with `x86_64-elf-gcc` and booted in QEMU; screens captured with the QEMU monitor's `screendump`. |
| Multilayer Perceptron | Saved parameters re-evaluated (95.8 %). Curves and grid search from the repository's `data/historic` files. |
| DSLR | `logreg_train.py` / `logreg_predict.py` re-run, compared with `dataset_truth.csv` (99.0 %). Charts computed from `dataset_train.csv`. |
| ft_linear_regression | `data.csv` and `values.txt` from the repository. The demo runs the same update rule in the browser. |
| Minishell, ft_irc | Built from the repositories; sessions recorded through a pseudo-terminal / two scripted IRC clients on localhost. |
| so_long | Map files rendered with the game's own XPM sprites (the build targets Linux MiniLibX, so this is not an in-game capture). |
| Matcha, Cloud-1 | Diagrams derived from the migrations, Compose files, Nginx config and Ansible roles. |

## Deployment (GitHub Pages)

The workflow `.github/workflows/deploy.yml` builds the site and publishes `dist/` on every push to `main`.

One-time setup on GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

### Why direct links work without a server

GitHub Pages cannot rewrite `/work/matcha` to `index.html`. `scripts/prerender.mjs` therefore writes a real `dist/work/matcha/index.html` for every route, each with its own title, description, canonical URL and Open Graph tags. `404.html` is a copy of the app, so unknown URLs show the site's own 404 page.

## Maintenance notes

- **Résumé button**: hidden until `site.resume` is set in `src/content/site.ts` (e.g. `'/resume.pdf'`, with the file in `public/`).
- **Location** in the contact section: hidden until `site.location` is set.
- **Source links**: projects show "source available on request" until their `source` field is changed to `{ public: true, url: '…' }`.
- Fonts (Geist, Geist Mono) are self-hosted through `@fontsource-variable`. No external requests.
- Reduced motion is respected everywhere: the hero renders a still frame, reveals are disabled and animations are paused.
